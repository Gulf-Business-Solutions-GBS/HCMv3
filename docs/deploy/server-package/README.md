# Server deployment package - the parts that are written by hand

Everything the Webtropia server needs, apart from the three things that are
produced by a build:

| In this folder | What it does |
|---|---|
| `Deploy-OnServer.ps1` | Runs the whole deployment on the server |
| `Enable-Https.ps1` | Certificate setup, for a new server only |
| `DEPLOY-README.md` | The instructions that ship inside the package |
| `sql\01-create-database.sql` | Creates `HCMv3Db` and the `hcm_app` login |
| `sql\03-demo-data.sql` | Optional two demo employees |

They are here because they are not generated by anything: they were written
once and are edited by hand. They used to live only in `C:\GBS\HCM\HCMv3-Deploy`
on the build machine, and were lost when that folder was reused for something
else - recovered only because an old `.7z` still held a copy.

## Assembling a package

Copy this folder's contents into an empty folder, then add the three built
parts beside them:

| Added by the build | How |
|---|---|
| `api\` | `dotnet publish src/HCMv3.Web.Host/HCMv3.Web.Host.csproj -c Release -o <pkg>\api` |
| `web\` | `npx gulp build` then `npx ng build --configuration production` in `angular\`, then copy `dist\browser\*` plus `angular\web.config` |
| `sql\02-schema-all-migrations.sql` | `dotnet ef migrations script --idempotent` from `src\HCMv3.EntityFrameworkCore` |

Then fill in the server-specific values (see below), check the migration count
in `Deploy-OnServer.ps1` and `DEPLOY-README.md` still matches the number of
migration files, and compress the folder with `7z a` followed by `7z t`.

## The values that are not in this repository

Three values are server-specific and one of them is a password, so they are
kept in `C:\GBS\HCM\deploy-secrets.json` on the build machine, outside the
repository:

- the `hcm_app` database password - replaces `REPLACE_WITH_APP_PASSWORD` in
  `sql\01-create-database.sql`, and goes into the connection string in
  `api\appsettings.Production.json`
- the server hostname, for `appsettings.Production.json` and
  `web\assets\appconfig.production.json`
- the AI assistant settings block

If that file is ever lost, the password can be read from
`api\appsettings.Production.json` inside any previously built `.7z`.

**Do not paste the password back into this folder.** A copy committed here is
a copy in every clone, every backup and every archive of this repository,
including ones that outlive the server.
