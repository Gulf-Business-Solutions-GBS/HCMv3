# Importer gaps -- the ready-made worklist

Every gap in Stimulsoft's `StiDevExpressHelper` reports itself through the helper's own `ThrowError`
path, so this histogram is not an estimate: it is a complete census of what the importer does not
understand across all 481 converted reports.

**7,936 warnings, 106 distinct kinds.** Regenerate with:

    dotnet run --project .\HCMv3.RepxToMrt -c Release -- .\out\repx-all .\out\mrt-all
    # histogram lands at the end of out\mrt-all\_convert.log; per-report detail in _warnings.tsv

## Triage, corrected against the one report actually taken end to end

The earlier triage called `root.CalculatedFields` the only functionally significant gap and filed the
rest as "per-control cosmetics". Porting `rptPayslipEn` showed that reading is too optimistic.

| Warning | Count | Real severity | Evidence from rptPayslipEn |
|---|---|---|---|
| `Connection.#FromAppConfig` | 788 | **Blocking, but trivially fixed once** | Every data source lands with an empty connection string. One line in the render host rebinds them all. |
| `Item*.StringFormat` | 1,362 | **Functional, not cosmetic** | DevExpress `TextFormatString` is dropped. A KWD amount printed as `178.833333` instead of `178.833`, a date as `04-Jul-07 12:00:00 AM` instead of `04-07-2007`. On a payroll document that is a defect, not polish. |
| `root.CalculatedFields` | 458 | **Blocking, silent** | `CalcNetPay`, `CalcAmount`, `CalcDateTime` all vanish; every expression referencing them renders blank with no warning at the point of use. |
| `Item*.Ref` | 1,362 | Benign | DevExpress serialization ids. |
| `Item*.BorderStyle` / `Padding` / `BorderWidthSerializable` | ~2,000 | Genuinely cosmetic | Visually indistinguishable in the rendered payslip. |
| `root.ObjectStorage` | 450 | Usually benign | Cached design-time data. Carries embedded images in a minority of reports -- worth a targeted check. |
| `root.Scripts` | 96 | **Blocking where present** | Report-level DevExpress script. Overlaps with the 266 code-behind files; must be reimplemented by hand. |
| `Query.Meta` / `Query.Columns` / `Query.#Table` | 154 | Benign | Cached result-set schema, regenerated by `StiDictionary.Synchronize()`. |
| `root.FormattingRuleSheet` | 30 | **Functional** | Conditional formatting (negative amounts in red, etc.) is silently lost. |
| `Item*.ParameterBindings` | ~250 | **Functional** | Subreport parameter wiring. This is what leaves every data band bound to the placeholder `"ds"`. |

### The gap that does NOT appear in this histogram at all

The single most expensive defect found while porting the payslip is **not reported as a warning**:
the importer writes every data band''s `DataSourceName` as the literal `"ds"` and every field
expression as `{ds.<Column>}`. It is not a "node not supported" -- the importer thinks it succeeded.
The result renders the full layout with every value cell blank, which is indistinguishable from
"this employee has no data". Any per-report acceptance test that only checks "the .mrt opens" or
"the PDF has pages" will pass a completely broken report.

Two further silent defects in the same class:

* Data-source parameters are emitted with `SqlDbType` 0, which is `BigInt`, not "unspecified" --
  so every string/date parameter fails at runtime with *Failed to convert parameter value from a
  String to a Int64*. The importer does try to fix this for strings, but tests
  `Expression.StartsWith("(System.String)")` against an expression it writes assembly-qualified as
  `"(System.String, mscorlib, ...)"`, so the test never fires.
* Controls are RENAMED when subreports are flattened into pages (`xrLabel11` -> `xrLabel110`,
  and an unrelated label inheriting the name `LoggedUserNme5`), which defeats any repair pass keyed
  on control name -- including recovering the dropped formats from the original `.repx`.
